## Резервні копії та Excel

У заголовку є **«Файл проєкту»**: збереження всіх анкет у JSON, імпорт із переглядом, додавання копій або відновлення всього простору з резервною копією попереднього стану. Пошкоджений файл не змінює поточні дані.

**«Експорт Excel»** у вузлі та **«Excel обладнання»** на сторінці обладнання формують редагований початковий шаблон із формулами, оформленням і малюнками. Вісім конструкцій перевірені в Microsoft Excel: 1088 числових зіставлень без розбіжностей. Схеми залишаються з шаблону й не перебудовуються за новою геометрією. Подробиці та порядок перевірки — [EXPORT.md](docs/EXPORT.md).

## Перший блок обчислень

Додано розрахункові зусилля, чотири перевірки прокладки для НУЕ/ГВ та нижню межу затягування з визначальною умовою. У блоці «Кріплення» можна ввести момент для перевірки конкретного затягу; нижня межа від цього поля не залежить. У заголовку мінімум округлюється вгору до цілого Н·м, як P88 Excel. Формули та звіряння — [FORCES.md](docs/FORCES.md), перевірки — `node tests/forces.cjs`.

Підключено міцність кріплення й чотири перевірки зрізу різьби: фактичні/допустимі напруження та запаси міцності для заданого моменту. Rp береться з актуальних матеріалів за температурою режиму. Для наскрізного болта різьба корпусу не застосовується. Формули, коефіцієнти та особливості Excel — [STRENGTH.md](docs/STRENGTH.md), перевірки — `node tests/strength.cjs`.

Обчислюється максимум за обмеженнями кріплення, різьби та підключених фланців, з округленням униз як P89 та визначальною умовою. N67 збережено дослівно. Обидві округлені межі повторно перевіряються за наявними умовами; несумісність до/після округлення й відсутні дані показуються явно. Поле заданого моменту ці перевірки не змінюють. Перевірки — `node tests/limits.cjs`, формули та особливості — [STRENGTH.md](docs/STRENGTH.md).

У налаштуваннях з’єднання для кожної деталі потрібно вибрати застосовність перевірки фланця та, якщо вона активна, заповнити D, Dw, Df, d₀, hf, h₂, s₁, s₂. Матеріал спільний з відповідною деталлю. Підключено σ₂ та приведені напруження перерізів А–А, B–B, C–C, моменти опору та верхні обмеження. За невизначеної застосовності результат залишається попереднім; за повних даних і виконаних перевірок обох округлених меж показується «Межі перевірено». Міграція збережених анкет не вимикає фланці приховано. Формули та звіряння 200 величин усіх 4 вузлів — [FLANGES.md](docs/FLANGES.md), перевірки — `node tests/flanges.cjs`.

Температурний блок також працює: α прокладки береться за точною або найближчою вищою температурою Б.2 (45→50, 90→100 °C). Розширення шпильки/болта в усіх режимах і температурний внесок ГВ прийняті нульовими. Для НУЕ обчислюються розширення пакета та Ft; потрібні α/E активних деталей. Подробиці — [THERMAL.md](docs/THERMAL.md), перевірки — `node tests/thermal.cjs`.

Також підключено блок податливості та коефіцієнта навантаження для НУЕ/ГВ: проміжні складові, суми й χ. Площі перерізів деталей А/Б можна ввести вручну; для кільцевого вузла порожні поля означають розрахунок за кільцевим полем прокладки, як у контрольному прикладі. Для нестандартної прокладки площі деталей задаються окремо. Подробиці: [податливість](docs/COMPLIANCE.md), перевірки: `node tests/compliance.cjs`.

Підключено `calculations.js`: ширини й площі прокладки, похідні діаметри та площі кріплення, суми різьбових і нерізьбових висот пакета. У розділі «З’єднання» задаються висоти деталей А/Б. Дані старих анкет збережені; нові висоти потрібно заповнити. Погоджене правило: при b₀ > 15 мм використовується 3,8√b₀, інакше b₀. Вихідне правило ширини з довідника Б.1 залишається явно позначеним у довідковій панелі.

Для шестигранної гайки береться висота з каталогу; ковпачкова потребує окремого значення висоти різьбової частини. Зміна діаметра, стандарту або типу гайки скидає це ручне значення. Невідомі висоти не замінюються нулями. Геометрична сума L* + L** не є готовою замовною довжиною кріплення. Повний контроль меж потребує визначеної застосовності фланців та всіх потрібних характеристик матеріалів.

Перевірки цього блока: `node tests/calculations.cjs`. Звіряння з контрольним вузлом і граничні випадки доповнюють `node test_core.cjs`.

Перша версія персонального опитувальника для вузлів фланцевих з’єднань.

Відкрийте `index.html` у сучасному браузері. Кнопкою **«Нова папка»** створіть потрібну структуру, наприклад **ХАЕС → 4 Блок → Насоси**. У відкритій папці натисніть **«Додати обладнання»**, створіть у ньому вузол і заповніть блоки ліворуч. Наявне обладнання можна перенести разом із вузлами кнопкою **«Перемістити»** на його картці. Пошук за назвою чи позначенням охоплює весь реєстр. Резервна копія JSON включає структуру папок. Дані автоматично зберігаються в цьому браузері. Файл Excel не змінюється.

Для локального сервера, якщо встановлений Python:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Відкрийте <http://127.0.0.1:4173>. Збереження для адреси сервера та для безпосередньо відкритого HTML є окремими. Для щоденної роботи використовуйте один спосіб запуску й один браузер. Очищення даних браузера видаляє локальні анкети; перед очищенням збережіть JSON через «Файл проєкту».

## Довідники

- `data.js` — додана база металів. Анкета зберігає марку, КП та опис виконання; властивості щоразу читаються з актуальної бази. Після заміни файлу оновіть сторінку. За відсутності точної температури для кожної характеристики вибирається найближча більша наявна температура; екстраполяції немає.
- `standards.js` — місце для погоджених значень із ТУ та ГОСТ. Внесіть назву документа й дані прокладки; для гайок і шайб заповніть `sizes`, використовуючи діаметр різьби як ключ. Одиниці вказані в назвах полів. Значення `null` означає, що даних поки немає. Приклади структури є в коментарях файлу. Після редагування оновіть сторінку.

Для гайки задаються `heightMm` та `threadEngagementMm`; для шайби — `thicknessMm`, `outerDiameterMm`, `innerDiameterMm`. Якщо шайби з обох боків, застосовується один матеріал та один набір розмірів.

## Межі першої версії

Працюють обладнання та вузли, анкети, конструктор деталей, довідники, геометрія, навантаження, міцність і контроль обох меж моменту. Зміни анкет зберігаються локально. JSON і початковий Excel доступні в інтерфейсі; наступний етап — приймання контрольних конструкцій із повною виробничою базою матеріалів.

## Повна автоматична перевірка

В анкеті працює перевірка чисел і взаємозалежних розмірів: помилки видно біля полів, є перехід до першої помилки. Некоректні значення блокують підтвердження розрахунку та Excel-експорт. Правила й допустимі автоматичні значення — [INPUT_VALIDATION.md](docs/INPUT_VALIDATION.md).

З папки проєкту, якщо встановлений Node.js:

```powershell
node scripts/check.cjs
```

Команда перевіряє синтаксис JavaScript, відповідність автономних каталогів та Excel-шаблону вихідним файлам, усі тести з `tests/`, основну логіку й 752 числові зіставлення з контрольними значеннями Excel. Нові файли тестів `tests/*.cjs` підключаються автоматично. Додаткові пакети та Python для цієї команди не потрібні.

У кінці показується кількість успішних перевірок і помилок; за будь-якої помилки команда повертає код 1. Вона не перебудовує каталоги, не перезаписує звіти чи контрольні файли та не змінює анкети.

Це автоматичні перевірки за збереженими контрольними даними. Новий перерахунок у Microsoft Excel і перевірка інтерфейсу виконуються окремо — порядок описано в [EXPORT.md](docs/EXPORT.md).

Додаткові сценарії: 48 комбінацій конструктора, пошкоджені JSON, відмови сховища, фоновий експорт і структура XLSX — [звіт про граничні випадки](docs/EDGE_CASES_2026-11-14.md).

Другий прохід охоплює зміни характеристик матеріалів, 36 перевірок усередині допустимих діапазонів, числове переповнення геометрії та відновлення великого проєкту на 4000 вузлів. Усі ці тести входять у ту саму команду.

## Нормативний каталог шайб

Оцифровано таблицю розмірів ГОСТ 11371-78 (М1–М48, 27 типорозмірів) у `standards/washers/gost-11371-78.json`. Таблиця містить внутрішній діаметр для класів точності А та С, зовнішній діаметр і товщину. Недоступні для класу С розміри М3,5, М33 і М39 зберігаються як `null`, а не як нуль. Виконання 2 дозволене лише для класу А та діаметрів від 5 мм.

У браузері без сервера використовується згенерований `standards.bundle.js`. Після редагування чи додавання JSON-стандартів виконайте:

```powershell
python scripts/build-standards.py
node test_core.cjs
```

Для збережених анкет без нових полів шайб застосовуються значення за замовчуванням: ГОСТ 11371-78, виконання 1, клас А. Розміри відображаються автоматично після вибору розташування шайб, стандарту, класу точності та діаметра різьби. За відсутності нормативного розміру анкета не позначатиме шайби заповненими.

Зверніть увагу: в наданому скриншоті для М2,5 зазначено `d₂=6,5`, тоді як у виданні ГОСТ 11371-78 (2006, зміни 1–3) — `d₂=6,0` мм. У базі використано 6,0 мм, розбіжність задокументована в метаданих джерела.

`standards.js` залишається тимчасовим сховищем параметрів прокладки та гайок, доки їх не перенесено до каталогу.

## Нормативна висота гайок за ГОСТ 5915-70

У `standards/nuts/gost-5915-70.json` збережено **лише номінальну висоту гайки `m`** для 22 розмірів М1,6–М48. Гайки — шестигранні, клас точності В. Діаметри М3,5, М14, М18, М22 та М27 у стандарті наведені в дужках і позначені як нерекомендовані, але їхні розміри залишаються доступними.

В редакторі вузла у блоці «Гайка» вибирається стандарт; `m` автоматично визначається за номінальним діаметром кріплення. Недоступні розміри не замінюються приблизними. Довжина зачеплення різьби **не є** висотою гайки й буде визначатися окремо за методикою розрахунку.

Щоб перебудувати автономний каталог після змін в `standards/nuts/` або `standards/washers/`, виконайте `python scripts/build-standards.py` та `node test_core.cjs`.

## Крок метричної різьби М6–М60

У `standards/threads/gost-24705-2004.json` наведено допустимі кроки різьби для 36 номінальних діаметрів М6–М60 (лише позиції стандарту, а не кожне ціле число). Кроки й розмежування великого та дрібних кроків — за ГОСТ 8724-2002; зв'язок із базовими розмірами — за ГОСТ 24705-2004.

У блоці «Кріплення» великий крок визначається автоматично, якщо для обраного діаметра він передбачений ГОСТ 8724-2002. Дрібний крок необхідно вибрати явно. Для М15, М17, М25, М26, М28, М32, М35, М38, М40, М50, М55, М58 великий крок у таблиці не заданий: користувач повинен вибрати один із доступних дрібних кроків. Для М30×3 та М33×3 відображається позначка нерекомендованості.

Якщо номінальний діаметр змінюється, попередній явно вибраний крок скидається. У випадку відсутньої або неприпустимої комбінації діаметра і кроку розділ «Кріплення» не вважається заповненим. Для нових вузлів `pitch` зберігається як порожній рядок: це **автоматичний великий крок**, а не жорстко задане числове значення. У старих анкетах ці поля додаються без втрати інформації.

Оновлення довідника: `python scripts/build-standards.py`, перевірки: `node test_core.cjs`.

## ГОСТ 9064-75 — гайки для фланцевих з’єднань

У `standards/nuts/gost-9064-75.json` оцифровано 14 типорозмірів М10–М60 (обмеження поточного етапу; стандарт охоплює і більші діаметри). Збережено **лише висоти**, потрібні для анкети:

- Тип А — шестигранна гайка: висота `H`.
- Тип Б — ковпачкова гайка: **загальна** висота `l₁`; це не висота опорної частини й не довжина зачеплення різьби.

Для М10 тип Б відсутній (записано `null`). М22, М27, М52 і М60 наведені в стандарті в дужках і позначені як нерекомендовані. Виконання 1–3 типу Б відрізняються іншими розмірами; вибір виконання не впливає на спільний табличний ряд `l₁` і тут поки не здійснюється.

Після вибору ГОСТ 9064-75 у блоці «Гайка» з’являється вибір типу А/Б. При зміні стандарту тип скидається на А. Якщо комбінації типу й діаметра немає в оцифрованому каталозі, підстановка заборонена й блок не вважається заповненим. Для ГОСТ 5915-70 поведінка лишається незмінною.

## Графітові прокладки — таблиці Б.1 і Б.2 (без номера ТУ)

`standards/gaskets/graphite-annex-b1-b2-unidentified.json` — оцифровані значення **зі скриншота користувача**:

- Б.1: модуль Юнга `Eпр = 100 МПа`; ефективна ширина `b` дорівнює ширині поля прокладки; коефіцієнт `m = 1,6` для рідин, `2,5` для повітря/пари/газових сумішей, `3,2` для газів з високою проникною здатністю (водень, гелій); `q0=5`, `qmin=3,5`, `qmax=200 МПа`.
- Б.2: коефіцієнт лінійного розширення `α` у одиницях `10⁻⁶/°C`: 50→0,21; 100→0,43; 150→0,50; 200→0,69; 250→1,00; 300→1,33; 350→1,50; 400→1,61.

**Увага:** на фрагменті немає номера чи редакції ТУ і не підтверджено відповідність конкретній марці прокладки `ТМГ-ЛА-П1/А1`. Поле `document` залишене `null`, а статус джерела — `screenshot_only`. Скриншот до публічного репозиторію не додається. Не використовуйте ці значення як підтверджені нормативні без встановлення первинного документа.

Наразі передбачено **лише один набір нормативних характеристик прокладки**. Він використовується автоматично: у блоці «Прокладка» немає списку вибору стандартів. Нові та раніше збережені вузли автоматично отримують посилання на таблиці Б.1–Б.2. Відображаються параметри `Eпр`, `q0`, `qmin`, `qmax`, правило для `b`, коефіцієнт `m` за середовищем НУЕ/ГВ та `α` за табличною температурою. Для α використовується точна або найближча вища доступна температура Б.2; вище останньої точки значення недоступне. Геометрія, податливість і температурний внесок підключені; міцність і межі моменту — наступні етапи.

Згенеруйте автономний каталог: `python scripts/build-standards.py`; перевірте логіку: `node test_core.cjs`.
