# Прокладки

Перша версія персонального опитувальника для вузлів фланцевих з’єднань.

Відкрийте `index.html` у сучасному браузері. Створіть обладнання, усередині — вузол, і заповніть блоки ліворуч. Дані автоматично зберігаються в цьому браузері. Файл Excel не змінюється.

Для локального сервера, якщо встановлений Python:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Відкрийте <http://127.0.0.1:4173>. Збереження для адреси сервера та для безпосередньо відкритого HTML є окремими. Для щоденної роботи використовуйте один спосіб запуску й один браузер. Очищення даних браузера видаляє локальні анкети; імпорт/експорт планується наступним етапом.

## Довідники

- `data.js` — додана база металів. Анкета зберігає марку, КП та опис виконання; властивості щоразу читаються з актуальної бази. Після заміни файлу оновіть сторінку. За відсутності точної температури для кожної характеристики вибирається найближча більша наявна температура; екстраполяції немає.
- `standards.js` — місце для погоджених значень із ТУ та ГОСТ. Внесіть назву документа й дані прокладки; для гайок і шайб заповніть `sizes`, використовуючи діаметр різьби як ключ. Одиниці вказані в назвах полів. Значення `null` означає, що даних поки немає. Приклади структури є в коментарях файлу. Після редагування оновіть сторінку.

Для гайки задаються `heightMm` та `threadEngagementMm`; для шайби — `thicknessMm`, `outerDiameterMm`, `innerDiameterMm`. Якщо шайби з обох боків, застосовується один матеріал та один набір розмірів.

## Межі першої версії

Працюють обладнання та вузли, анкети, конструктор деталей, довідник матеріалів і локальне збереження. Центральні блоки та межі моменту відображають «Ще не розраховано». Інженерні формули, геометрія фланців, підбір різьби й точний експорт початкового Excel додаються після погодження. Значення з ТУ та ГОСТ не вигадані: незаповнені таблиці залишені порожніми.

Перевірка логіки, якщо встановлений Node.js:

```powershell
node test_core.cjs
```

## Нормативний каталог шайб

Оцифровано таблицю розмірів ГОСТ 11371-78 (М1–М48, 27 типорозмірів) у `standards/washers/gost-11371-78.json`. Таблиця містить внутрішній діаметр для класів точності А та С, зовнішній діаметр і товщину. Недоступні для класу С розміри М3,5, М33 і М39 зберігаються як `null`, а не як нуль. Виконання 2 дозволене лише для класу А та діаметрів від 5 мм.

У браузері без сервера використовується згенерований `standards.bundle.js`. Після редагування чи додавання JSON-стандартів виконайте:

```powershell
python scripts/build-standards.py
node test_core.cjs
```

Для збережених анкет без нових полів шайб застосовуються значення за замовчуванням: ГОСТ 11371-78, виконання 1, клас А. Розміри відображаються автоматично після вибору розташування шайб, стандарту, класу точності та діаметра різьби. За відсутності нормативного розміру анкета не позначатиме шайби заповненими.

Зверніть увагу: в наданому скриншоті для М2,5 зазначено `d₂=6,5`, тоді як у виданні ГОСТ 11371-78 (2006, зміни 1–3) — `d₂=6,0` мм. У базі використано 6,0 мм, розбіжність задокументована в метаданих джерела.

`standards.js` залишається тимчасовим сховищем параметрів прокладки та гайок, доки їх не перенесено до каталогу.

## Нормативна висота гайок за ГОСТ 5915-70

У `standards/nuts/gost-5915-70.json` збережено **лише номінальну висоту гайки `m`** для 22 розмірів М1,6–М48. Гайки — шестигранні, клас точності В. Діаметри М3,5, М14, М18, М22 та М27 у стандарті наведені в дужках і позначені як нерекомендовані, але їхні розміри залишаються доступними.

В редакторі вузла у блоці «Гайка» вибирається стандарт; `m` автоматично визначається за номінальним діаметром кріплення. Недоступні розміри не замінюються приблизними. Довжина зачеплення різьби **не є** висотою гайки й буде визначатися окремо за методикою розрахунку.

Щоб перебудувати автономний каталог після змін в `standards/nuts/` або `standards/washers/`, виконайте `python scripts/build-standards.py` та `node test_core.cjs`.
