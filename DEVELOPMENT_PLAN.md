# План розробки «Прокладки»

План від 13.11.2026. Початкова версія: `eca7996` (`feat/graphite-gasket-tu-annex-b`).

> **Цільова платформа — тільки десктоп:** Інтерфейс створюється виключно як автоматизоване робоче місце інженера на настільному ПК (десктоп). Оптимізація та перевірки під мобільні пристрої (телефони) не виконуються й перебувають поза межами завдань для розробників та ШІ-агентів.

Мета наступної робочої версії — розрахувати допустимий діапазон моменту затягування для підтримуваної конструкції вузла, показати його обмежувальні перевірки та проміжні результати. Методика погоджується з власником розрахунку по блоках. Додаток 10 виключений.

## Поточний стан

Оновлення 14.11.2026: виконано наскрізну звірку з Microsoft Excel — 752 числові зіставлення без розбіжностей арифметики. Для вузла №4 користувач підтвердив товщину 1 мм; контрольна копія перерахована з цим виправленням. Вузли №1–3 проходять перевірки меж із поточними матеріалами та погодженими тимчасовими E/α 25Л з Excel. Для вузла №4 погоджено пропуск внутрішньої різьби чавунного корпусу без Rp як у Excel: максимум числовий, перевірка позначена пропущеною, а не виконаною. Деталі — `docs/VERIFICATION_2026-11-14.md`.

Готові робочий стіл обладнання, вузли, анкети, конструктор додаткових елементів, вибір матеріалу та КП, локальне збереження. Підключені каталоги шайб, гайок двох стандартів, кроків різьби та характеристик графітової прокладки. Є генератор автономного каталогу й тести.

Центральні блоки обчислюють геометрію, суми висот пакета, податливості, χ, температурний внесок, навантаження, міцність кріплення/різьби/активних фланців та обидві межі моменту. Округлені межі перевіряються незалежно. Для шестигранної гайки в суму різьбових висот входить таблична висота; для ковпачкової потрібна висота різьбової частини. JSON та експорт початкового Excel реалізовані: 1088 числових зіставлень у Microsoft Excel без розбіжностей; подробиці — `docs/EXPORT.md`. Виробничий контроль із повною базою ще потребує E/α 25Л.

Зберігаємо персональний локальний режим, наявний інтерфейс і один поточний набір даних на вузол. Значення металів читаються з актуальної бази. Імпорт/експорт робочого простору та експорт Excel — різні задачі.

### Питання, які треба закрити до залежних формул

1. **Прокладка:** підтвердити позначення/застосовність ТУ для єдиного набору Б.1–Б.2. Правило α вже погоджене й реалізоване: точна або найближча вища таблична температура, зокрема 20→50 °C.
2. **Різьба:** погодити формули похідних діаметрів, довжини гладкої й різьбової частин, зачеплення з гайкою та корпусом. Табличну загальну висоту гайки не підставляти замість зачеплення.
3. **Геометрія:** визначити потрібні розміри для кожної основної деталі й правила її розрахункової висоти та площі. Для нестандартної прокладки зберігаються дві ручні площі з погодженим змістом.
4. **Температура складання:** явно погодити використовуване значення та його роль у формулах.
5. **Перевірки:** погодити перелік критеріїв нижньої та верхньої меж. Окремо визначити участь максимального тиску на прокладку, різьби, сумісних напружень і фланців; не додавати нові критерії під виглядом точного перенесення Excel.

Ці питання розбираються перед відповідним блоком. Вони не блокують резервне копіювання, розмітку полів та інші незалежні задачі.

## 3–5. Підключення розрахунку

Податливості та χ реалізовані й звірені на 20 проміжних значеннях I/J4–18. Температурний блок також підключений. Для повного контрольного прикладу з актуальною базою потрібно доповнити E й α матеріалів СЧ25 та 25Л; прогалини записані в `docs/COMPLIANCE.md` та `docs/THERMAL.md`.

Погоджені температурні правила реалізовані: α прокладки з найближчої вищої табличної температури; розширення кріплення в усіх режимах і температурний внесок ГВ — нулі. Деталі — `docs/THERMAL.md`, перевірки — `tests/thermal.cjs`.

Послідовність блоків: податливості деталей і коефіцієнт навантаження → температурні складові → зусилля та тиск на прокладку → герметичність і мінімум → міцність кріплення, різьби та фланців → максимум і підсумковий діапазон.

Зусилля, чотири перевірки прокладки й нижня межа вже підключені; визначальна умова показується, округлення мінімуму відтворює P88. Формули, особливість знака Ft, межі застосування та звіряння — `docs/FORCES.md`.

Міцність кріплення й різьби також підключена для заданого моменту: напруження, допустимі значення, запаси, фактичні Rp й температури. Звірено 43 величини з Excel; перевірки — `tests/strength.cjs`, методика — `docs/STRENGTH.md`.

Верхню межу реалізовано зі збереженням N67 та переліку обмежень Excel, відповідно до чинної вимоги не змінювати математику. Додатково перевіряються округлені межі за наявними умовами, без зміни заданого моменту. Звірено ще 15 величин максимуму; перевірки — `tests/limits.cjs`. Незалежний контроль показує можливі розбіжності з перевірками σ₃/σ₄, кручення чи qmax.

Геометрія Q–X, σ₂, приведені напруження, моменти опору й верхні обмеження фланців підключені. Застосовність задається для кожної деталі; відсутня активна геометрія блокує максимум, а невизначена застосовність залишає результат попереднім. Звірено 200 величин усіх 4 вузлів і 14 верхніх обмежень; перевірки — `tests/flanges.cjs`, карта полів та особливості — `docs/FLANGES.md`. За визначеної застосовності й виконаних перевірок округлених меж доступний повний контроль за перенесеною методикою.

Після завершення обох меж показуємо:

- стан «Допустимого діапазону немає», якщо межі несумісні, включно з випадком після округлення;
- повідомлення про неможливість повного розрахунку, якщо потрібна перевірка не виконана.

Проміжні величини не округлюються для подальших обчислень тільки заради їх відображення. Числові допуски звіряння визначаються для конкретних величин до приймання блока.

## Організація роботи

- Розробник готує карту полів, реалізацію та звіряння; власник розрахунку погоджує інженерні формули, їх застосовність і спірні відмінності джерел.
- Наступну задачу беремо з конкретним результатом і умовою завершення; не переносимо всю книгу одним неперевіреним блоком.
- Завершені каталоги варто зафіксувати в базовій гілці перед новими незалежними гілками; публікація та злиття в GitHub — окремі дії.
- Для змін каталогів: перебудова `standards.bundle.js` і наявні тести. Для нового обчислення: числова перевірка, а для нового поля — перевірка інтерфейсу та збереження.
- При додаванні формул оновлювати карту проєкту й опис готових можливостей; підтримувати один актуальний план.

План не призначає календарних строків. Погоджений пропуск різьби чавунного корпусу без Rp відтворює Excel; для реальної перевірки цієї різьби надалі потрібен критерій чавуну. Розбіжності старих констант прокладки вузла №4 з каталогом зафіксовані у звіті. СЧ25 уже має E/α; у виробничому data.js для 25Л вони ще відсутні, а для поточної звірки використані числа Excel лише в контрольному наборі за дозволом користувача. JSON та початковий Excel завершені. Наступні задачі — приймання контрольних конструкцій і заповнення відсутніх E/α 25Л; критерій внутрішньої різьби чавуну залишається окремим інженерним питанням. Перевірки обох округлених меж залишаються незалежним контролем перенесеної методики.
